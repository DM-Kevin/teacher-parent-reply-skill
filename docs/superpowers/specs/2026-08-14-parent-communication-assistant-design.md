# 家长沟通助手 Skill 设计文档

## 1. 项目目标

为小学一至六年级教师提供一个本地家长沟通助手，解决教师在面对敏感、强势、容易将问题反馈理解为“老师针对孩子”的家长时，需要反复询问 AI、组织措辞时间过长的问题。

Skill 不以讨好家长或赢得教育理念争论为目标，而是帮助教师：

- 沟通前明确目标、事实和边界；
- 沟通中快速判断是否需要回复以及回复多少；
- 生成自然、简短、符合教师本人语气的微信回复或电话／面谈提纲；
- 沟通后整理结论，经教师确认后沉淀到本地档案；
- 通过教师语气档案、学生档案和历史沟通记录逐步提高建议质量。

体验目标是让普通问题尽量在 5 分钟内完成沟通准备，避免教师陷入长篇解释和教育理念辩论。

## 2. 设计原则

### 2.1 先判断是否需要回复

Skill 不默认每条家长消息都需要正式回应。每轮先判断应该正式回复、简短确认、结束话题，还是转电话／面谈。

### 2.2 事实与判断分离

将教师输入区分为已确认事实、教师观察和主观判断。只有已确认事实可以直接陈述；教师观察必须用观察性表达；主观判断不能被当作事实写入回复或长期档案。

### 2.3 不以空泛表扬换取配合

可以使用真实、具体的正向观察建立合作感，但不得虚构学生优点，也不得用过度道歉或无边界承诺安抚家长。

### 2.4 像教师本人，而不是像 AI

回复默认简短、自然、具体，并优先使用教师确认过的表达偏好。避免“底层能力、全面成长、教育的本质”等论文式或明显 AI 化表达。

### 2.5 本地保存、按需读取

档案保存在教师指定的本地目录。每次先读取精简索引，命中学生后才读取该生当前概况；仅在问题涉及历史事件时检索相关沟通记录。

### 2.6 长期信息必须经教师确认

AI 可以生成建档内容、沟通总结和语气更新建议，但写入长期档案前必须由教师确认。

## 3. 总体架构

采用“Markdown 档案＋辅助脚本”的混合架构：

- AI 负责理解语境、区分事实与判断、分析沟通状态、生成话术和提炼摘要；
- Python 脚本负责查找学生、处理重名、创建目录、维护索引、备份和安全写入；
- Markdown 保存教师偏好、学生概况和沟通记录，便于教师直接查看和修改；
- `SKILL.md` 负责规定交互流程、读取顺序、输出格式和风险边界。

不采用纯提示词方案，避免目录结构漂移、重复建档和索引漏更新；首版不采用 SQLite，避免数据对教师不透明以及不必要的复杂度。

## 4. Skill 目录

```text
parent-communication-assistant/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   └── manage_profiles.py
└── references/
    ├── communication-strategies.md
    ├── grade-guidance.md
    ├── profile-schema.md
    └── risk-boundaries.md
```

各组件职责：

- `SKILL.md`：定义初始化、建档、沟通前预案、实时陪聊、结束和保存流程；
- `manage_profiles.py`：初始化档案、查找学生、创建目录、处理同名、保存记录、更新索引、升年级、备份和校验；
- `communication-strategies.md`：常见家长回应类型及处理方法；
- `grade-guidance.md`：小学一至六年级的沟通侧重点；
- `profile-schema.md`：教师档案、学生概况、沟通记录的字段规范；
- `risk-boundaries.md`：受伤、欺凌、严重纪律、投诉和责任争议等高风险场景的处理边界。

代码中的注释必须使用中文且尽量详细。脚本只执行确定性档案操作，不判断家长心理，也不生成沟通内容。

## 5. 本地数据目录

真实档案不得放在 Skill 安装目录内，避免 Skill 更新或重装时覆盖数据。首次使用时默认建议保存到用户“文档”目录下的`家长沟通档案/`，同时允许教师选择其他本地目录。

```text
家长沟通档案/
├── 教师档案/
│   ├── 表达偏好.md
│   └── 已确认表达样本.md
└── 学生档案/
    ├── 学生索引.md
    ├── 张三-三年级2班/
    │   ├── 当前概况.md
    │   └── 沟通记录/
    │       └── 2026-08-14-作业完成问题.md
    └── 李四-五年级1班/
        ├── 当前概况.md
        └── 沟通记录/
```

Skill 不上传档案，不自动同步。首次初始化后，将档案根目录位置和数据结构版本保存到用户主目录下的`.parent-communication-assistant/settings.json`。该设置文件只保存路径和版本号，不保存学生或家长信息。如果路径失效，必须要求教师重新选择，不得擅自在其他位置新建另一套档案。

## 6. 首次初始化

### 6.1 教师语气档案

首次使用提供两种方式：

1. 上传 3～5 组历史家长对话截图，或粘贴 8～15 条教师本人发过的消息；
2. 跳过样本，选择基础风格，后续逐步学习。

历史样本最好覆盖表扬、作业提醒、行为反馈和回应质疑等不同场景。

上传截图后执行以下流程：

1. 识别对话双方；
2. 请教师确认哪一侧是自己发送的内容；
3. 只分析教师表达，不模仿家长语气；
4. 提取称呼、平均长度、直接程度、常用语气词、表情、分段习惯、开场、收尾和不喜欢的表达；
5. 展示语气画像并生成一条模仿测试消息；
6. 教师确认“像我”后写入`表达偏好.md`。

原始截图和完整历史对话默认不长期保存，只保留经教师确认的风格规则和少量代表性表达样本。

教师跳过初始化时使用默认风格：自然、简短、具体、尊重但不过度讨好。

### 6.2 新学生建档

首次涉及某位学生时，只询问四个必填项：

- 年级；
- 班级；
- 学生姓名；
- 本次沟通问题。

教师可以自由补充学生表现、家庭沟通背景或历史事件。AI 从自由描述中提取结构化信息，展示给教师确认后，再由脚本创建学生目录和索引记录。

允许保存真实姓名，但应提醒教师不要录入身份证号、家庭住址、电话号码等与沟通无关的敏感信息。

## 7. 入口与任务路由

教师不需要记忆命令，Skill 根据自然语言自动识别四类任务：

1. 沟通前预案，例如“我准备跟张三妈妈聊最近不交作业的问题”；
2. 沟通中陪聊，例如“家长回复我：小学作业没什么意义”；
3. 电话／面谈准备，例如“明天要和李四爸爸面谈”；
4. 沟通结束，例如“聊完了，帮我整理保存”。

进入具体学生后按以下顺序读取：

1. 读取精简的`教师档案/表达偏好.md`；
2. 读取`学生档案/学生索引.md`；
3. 按姓名、年级和班级匹配目标学生；
4. 命中后读取该生`当前概况.md`；
5. 仅当本次问题涉及历史事件时，检索相关沟通记录。

姓名重复时必须展示年级、班级和学生编号让教师确认，不得自行猜测。学生目录默认使用`姓名-年级班级`；出现同名同班学生时，目录名追加学生编号，例如`张三-三年级2班-S0002`。

## 8. 沟通前预案

首先将问题分类为学习表现、作业与习惯、课堂纪律、同伴冲突、情绪与心理状态、安全／受伤／欺凌、对教师或学校的质疑，或其他自定义问题。

预案包含：

1. 本次核心目标；
2. 最低目标与沟通边界；
3. 已确认事实、教师观察和主观判断；
4. 家长关注点、敏感点和偏好的表达方式；
5. 基于真实观察的推荐开场；
6. 需要陈述的核心事实；
7. 家长可能出现的回应；
8. 每个异议的一条简短回应；
9. 学校与家庭各自的下一步行动；
10. 可以结束沟通的信号。

预案的目标是完成事实告知、行动协商和边界确认，不追求让家长接受教师的全部教育观点。

## 9. 沟通中回复决策

每收到一条家长消息，按以下顺序处理：

1. 明确本轮沟通目标；
2. 判断家长是在询问事实、表达情绪、拒绝配合、转移话题，还是展开观点争论；
3. 检查是否掌握足够事实；
4. 选择正式回应、简短确认、到此结束或转电话／面谈；
5. 按教师语气生成内容。

回复动作分为四类：

| 判断 | Skill 行为 |
|---|---|
| 需要解决具体问题 | 生成可直接发送的回复 |
| 家长只是表达立场 | 建议一句确认，不展开辩论 |
| 事情已经说清楚 | 明确提示可以结束，不必继续解释 |
| 文字沟通风险升高 | 建议暂停微信，转电话、面谈或同步学校负责人 |

如果缺少关键事实，只询问一个最必要的问题。教师处于实时沟通时，同时提供一条临时安全回复，例如：“我看到您的消息了，这个情况我再核实一下，确认后尽快回复您。”

## 10. 微信回复规则与格式

微信回复遵循以下规则：

- 最佳回复放在第一位；
- 默认控制在一个微信气泡内，约 60～120 字；
- 复杂情况最多约 180 字，除非教师明确要求展开；
- 一条回复只解决一个核心问题；
- 先接住核心顾虑，再陈述具体事实，最后给出下一步行动或收尾；
- 不虚构表扬，不作无法兑现的承诺，不过度道歉；
- 不用抽象教育理论与家长辩论；
- 优先匹配教师本人表达偏好。

标准输出：

```text
【建议动作】
简短回复／正式回应／到此结束／转电话面谈

【可直接发送】
具体回复内容

【表达策略】
一句话解释为什么这样处理。

【避免表达】
一句话提示本轮不要争论或不要承诺什么。
```

## 11. 电话与面谈模式

电话／面谈模式生成可照着使用的提纲：

```text
30 秒开场
→ 具体事实
→ 听家长表达
→ 回应核心顾虑
→ 提出家校双方行动
→ 确认共识
→ 礼貌结束
```

同时提供：

- 家长可能提出的 3 个异议；
- 每个异议的一句话回应；
- 不应当场承诺的内容；
- 谈话失控时如何暂停并另约时间。

## 12. 年级适配

- 一、二年级：侧重习惯培养、入学适应和家校协作；
- 三、四年级：侧重规则意识、学习自主性和同伴关系；
- 五、六年级：侧重责任感、独立沟通和青春期前后的心理变化。

年级适配只调整沟通重点和行为期待，不对学生作年龄刻板判断。

## 13. 档案字段与按需加载

### 13.1 学生索引

索引只保存检索必需的信息：

```text
S0001｜张三｜三年级｜2班｜最近更新：2026-08-14
S0002｜李四｜五年级｜1班｜最近更新：2026-08-10
```

家长特点不放入总索引，避免每次读取其他学生的无关信息。学生编号用于处理同名学生。

### 13.2 当前概况

`当前概况.md`只保留当前仍然有效的信息：

- 学生基本信息；
- 已确认的长期表现；
- 已采取的支持措施；
- 家长关注点与沟通偏好；
- 尚未解决的问题；
- 最近一次沟通结论；
- 信息更新时间。

档案使用客观、可验证的描述。例如记录“家长对作业必要性持保留态度，偏好简短、具体的沟通”，不得记录“家长油盐不进、不讲道理”。

### 13.3 单次沟通记录

单次记录包含：

- 日期和渠道；
- 本次问题；
- 已确认事实；
- 家长核心关注；
- 教师实际采取的回应；
- 达成的共识；
- 待跟进事项；
- 是否需要更新长期概况。

默认不保存完整聊天原文和截图。只有教师明确要求时才保存，并再次提示可能包含隐私信息。

## 14. 沟通结束与持续学习

沟通结束时先询问：

> 本次实际发送内容是直接采用建议稿，还是有所修改？如有修改，请粘贴最终发送版本。

语气学习规则：

- 临时修改一次，只记录本次情况；
- 同类修改连续出现两次，提示发现可能的表达习惯；
- 连续出现三次，建议更新`表达偏好.md`；
- 教师确认后才更新；
- `已确认表达样本.md`只保留少量代表性样本，不无限积累；
- 日常生成只读取精简表达偏好，语气不稳定时才读取样本文件。

档案写入顺序：

1. AI 生成结构化总结；
2. 教师确认或修改；
3. 脚本新增沟通记录；
4. 仅将长期有效的信息合并到`当前概况.md`；
5. 更新索引中的年级、班级和最近日期；
6. 写入前备份将被修改的文件。

## 15. 风险边界

遇到学生受伤、欺凌指控、严重纪律问题、家长投诉教师或可能涉及责任认定的情况，进入高风险模式：

- 只陈述已经确认的事实；
- 不替学校认责；
- 不作无法保证的承诺；
- 提醒教师保留沟通记录；
- 建议按照学校流程同步班主任、年级负责人或管理人员；
- 优先转正式沟通渠道，不在微信中持续争论。

Skill 不进行心理诊断，不给学生或家长贴人格标签，也不代替学校的正式处置流程。

## 16. 异常处理与数据安全

- 找不到档案根目录：要求重新选择，不在其他位置擅自创建；
- 匹配到同名学生：展示年级、班级和编号供教师确认；
- 索引与目录不一致：停止写入并展示修复预览；
- 写入失败：保留旧文件，不留下半写状态；
- 截图无法辨认：请教师粘贴关键文字，不猜测；
- 缺少关键事实：提供临时确认回复，并只追问一个必要问题；
- 家长连续升级冲突：停止继续生成辩论材料，建议转正式沟通渠道。

脚本应采用临时文件加原子替换的方式写入，并在修改前创建可恢复备份。

## 17. 验收标准

### 17.1 功能验收

1. 新教师能够通过历史对话生成并确认语气档案；
2. 新学生能够通过四个必填项和自由描述完成建档；
3. 已有学生只加载索引、当前概况和相关历史；
4. 微信回复默认控制在一个气泡内；
5. 对无需继续争论的消息能够建议收尾或不回复；
6. 不虚构学生表现，不把主观判断写成事实；
7. 电话／面谈能够生成完整且简洁的提纲；
8. 沟通结束后必须确认总结才写入；
9. 同名学生、升年级和写入失败不会破坏档案；
10. 回复能够体现教师确认过的语气偏好。

### 17.2 场景验收

使用真实负面样本验证：当家长认为小学作业意义不大、继续讨论教育理念并指出回复“像 AI”时，Skill 应做到：

- 不生成长篇教育理论；
- 不试图证明家长观点错误；
- 用自然短句说明学校当前安排和下一步行动；
- 必要时承认上一条表达过于正式并自然收尾；
- 在事实和行动已经说明后提示教师结束话题。

### 17.3 脚本验收

覆盖以下自动化测试：

- 初始化空档案目录；
- 创建新学生；
- 精确查找学生；
- 同名学生消歧；
- 更新学生概况和索引；
- 新增沟通记录；
- 升年级与目录重命名；
- 索引不一致时拒绝写入；
- 写入失败时回滚；
- 备份文件可恢复。

## 18. 首版范围外

首版不包含：

- 自动读取微信或监控剪贴板；
- 自动判断教师在微信中是否修改了建议稿；
- 云端同步、多人协作或学校管理后台；
- 学生成绩分析和教学管理；
- 自动向家长发送消息；
- 用数据库替代可读的 Markdown 档案。

这些功能只有在首版实际使用证明必要后再考虑。
